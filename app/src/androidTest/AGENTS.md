# Purpose
Device regressions that need a real Android runtime: app-lock lifecycle, protected-screen
enforcement, and the certificate floor on the app's own HTTPS path.

# Ownership
Owns `LockRecreationTest` and `CertFloorDeviceTest`, and future tests requiring a real Activity
lifecycle or the platform's own TLS stack.

# Local Contracts
- Use a disposable emulator and synthetic in-memory lock state; restore the process singleton
  after each test.
- Block derivation deterministically so the replacement activity starts before stale setup
  completes.
- TLS refusal tests go through `driveApi` and attribute strength failures to the floor;
  wrong-hostname, untrusted-root and SHA-1 failures come from platform verification instead.
  The explicit baseline uses the default platform connection without the floor and must
  accept the RSA-2047 and weak-intermediate controls. Android already refuses SHA-1;
  its test checks that earlier platform rejection. P-224 has policy-level coverage because the native TLS
  stack may not negotiate it. Refusals assert no server request line.
- The strong-certificate control also verifies that a wrong leaf pin fails through the
  production adapter before any request line, so pinning cannot replace the strength floor.
- Read certificates from the androidTest assets generated by `scripts/tls-fixtures.sh`.
  Missing or malformed fixtures fail. Only absent fixture-CA trust may skip a normal build;
  `ci-tls-floor` builds with `-PscreenshotCa` and rejects nested `<skipped>` report elements,
  including assumption failures, rather than trusting the root's skipped count.

# Verification
- `./gradlew connectedDebugAndroidTest` (`ci-lock-recreation`, API 36).
- `./gradlew connectedDebugAndroidTest -PscreenshotCa=app/src/test/resources/tls/ca.pem
  -Pandroid.testInstrumentationRunnerArguments.class=org.kysecurity.drive.CertFloorDeviceTest`
  (`ci-tls-floor`, API 36), which fails if the tests skipped.
